# mailpilot

Локальный помощник по почте и календарю. Каждый день в 17:00 собирает письма с прошлой сводки,
раскладывает их по категориям, собирает переписки в цепочки и делает красивую HTML-сводку.
Смысловой анализ (суть переписок, проблемы на вашей стороне, конфликты, черновики ответов в вашем стиле)
делает агент в gigacode через скилл. **Ни одно письмо не отправляется без вашего явного «да».**

Всё работает только на вашей машине: почта читается через уже настроенный
[mcp-mail-server](https://github.com/yunfeizhu/mcp-mail-server), данные лежат в локальной базе SQLite,
сводка — один HTML-файл без внешних ресурсов.

## Как это устроено

```
cron 17:00 ──► mailpilot run ──► mcp-mail-server (IMAP) ──► база SQLite
                    │                                         │
                    │  правила: ПРОМ, INC, эскалация,         │  цепочки переписки
                    │  Jira, Confluence, уведомления          │  с историей за несколько дней
                    ▼                                         ▼
            HTML-сводка (сразу)        data/work/batch_NN.json (пакеты на анализ)
                                                │
gigacode + скилл mailpilot ◄────────────────────┘
   читает пакеты, пишет result_NN.json ──► mailpilot ingest ──► сводка дополнена смыслом и черновиками
   показывает черновики ──► ваше «да» ──► mailpilot send ──► reply_to_email
```

Почему так: в gigacode нет режима без окна, а вход через браузер живёт около часа, поэтому модель
вызывается только когда вы сами открываете gigacode. Всё, что можно сделать без модели, делает cron.

### Что видно в сводке

Сводка намеренно простая, сверху вниз:

1. **Важные люди** — письма от тех, кого вы указали в `digest.vip_senders`. Всегда первыми.
2. **Требует внимания** — переписки, где ждут вас, есть эскалация, проблема на вашей стороне или стоит
   подключиться. По каждой: суть всей переписки, предупреждения, что сделать, черновик ответа.
3. **Календарь** — остаток дня и следующий рабочий день, пересечения подсвечены.
4. **Остальное** — свёрнутые строки: Confluence, Jira, уведомления, переписки без вашего участия.

Разделы изначально свёрнуты: раскрываются кликом по заголовку или стрелке, а клик по карточке сверху сразу раскрывает нужный раздел. Справа вверху есть переключатель светлой и тёмной темы, выбор запоминается в браузере.

## Настройка под себя

У каждого свой `config.yaml`, поэтому сводка у всех своя. Например, вам важны обращения с ПРОМ,
а коллеге — переписка с юристами: коллега добавляет категорию «Юристы» с `importance: high`
(пример есть в `config.example.yaml`), а ПРОМ ставит в `low`.

- `importance` категории: `high` — в «Требует внимания» первыми, `normal` — там же после `high`,
  `low` — только в «Остальном», `hidden` — не показывать.
- `digest.vip_senders` — важные люди. Можно «Имя Фамилия», фамилию или адрес: mcp-mail-server отдаёт
  только адреса, поэтому фамилия ищется и латиницей (Зарецкий найдётся в `zaretskiy@…`).
- `escalation.people` — руководители: если они в адресатах, переписка помечается как эскалация.
- То же командами или словами агенту: `mailpilot vip add "Имя Фамилия"`, `mailpilot importance prom high`,
  `mailpilot mute --from адрес`, `mailpilot rule add …`.

## Установка

Нужны Python 3.10+, [uv](https://docs.astral.sh/uv/), Node.js 22.13+ (для mcp-mail-server).

```bash
git clone <ваш репозиторий> mailpilot
cd mailpilot
uv sync
uv run mailpilot demo --open      # демо-сводка на выдуманных письмах, почта не нужна
uv run mailpilot init             # создаст config.yaml и .env
```

Дальше:

1. В `config.yaml` впишите свои адреса (`me.addresses`), название своей системы и команды
   (`me.my_side_keywords`), параметры почты в `mcp.env` — те же, с которыми у вас уже работает mcp-mail-server.
2. В `.env` впишите пароль: `EMAIL_PASS=...`. Ни `config.yaml`, ни `.env` в git не попадают.
3. В категории `prom` впишите адрес группы ПРОМ, в `escalation.people` — руководителей,
   в `digest.vip_senders` — людей, чьи письма всегда должны быть наверху.
4. `uv run mailpilot doctor` — проверит соединение и покажет точные имена папок. Имя папки
   «Отправленные» впишите в `mailboxes.sent`.
5. `uv run mailpilot run --open` — первая сводка за последние сутки.
6. `uv run mailpilot learn --days 90` — соберёт ваши ответы из «Отправленных» как образцы стиля.

### Скилл для gigacode

Скопируйте папку `skill/mailpilot` в папку скиллов gigacode (как в документации gigacode;
формат стандартный: `SKILL.md` с описанием и папка `references`). Затем в gigacode:

- «разбери почту» — агент проанализирует пакеты и дополнит сводку;
- «покажи черновики» — пройдётся по черновикам, отправит только то, на что вы скажете «да»;
- «обнови профиль стиля» — после `mailpilot learn` напишет `data/style.md` (его можно править руками).

Если gigacode запускается не из папки mailpilot, скажите агенту путь к ней.

### Запуск по расписанию в 17:00

**Linux и macOS** (`crontab -e`), по будням:

```
0 17 * * 1-5 cd /путь/к/mailpilot && /путь/к/uv run mailpilot run >> data/cron.log 2>&1
```

Полный путь к `uv` покажет `which uv`. На macOS cron может потребовать разрешения «Полный доступ к диску».

**Windows** (Планировщик заданий), по будням:

```
schtasks /Create /TN mailpilot /SC WEEKLY /D MON,TUE,WED,THU,FRI /ST 17:00 ^
  /TR "cmd /c cd /d C:\путь\к\mailpilot && uv run mailpilot run >> data\cron.log 2>&1"
```

На Windows календарь читается из десктопного Outlook (нужен запущенный Outlook в той же учётной записи).
На macOS и Linux встречи берутся из писем-приглашений.

## Команды

| Команда | Что делает |
|---|---|
| `mailpilot run [--open]` | Забрать почту, собрать сводку и пакеты на анализ (для cron) |
| `mailpilot fetch` | Только забрать новые письма |
| `mailpilot ingest` | Принять результаты анализа от агента и пересобрать сводку |
| `mailpilot render [--open]` | Пересобрать последнюю сводку |
| `mailpilot status` | Состояние анализа и черновиков (JSON) |
| `mailpilot drafts` | Черновики на согласование |
| `mailpilot draft show/edit/reject ID` | Посмотреть, поправить (`--text`, `--file` или редактор), отклонить |
| `mailpilot send ID` | Отправить черновик после подтверждения «да» |
| `mailpilot learn [--days 90] [--style-only]` | Образцы ответов из «Отправленных» и пакет для профиля стиля |
| `mailpilot categories` | Список категорий и их важность |
| `mailpilot importance КАТЕГОРИЯ high\|normal\|low\|hidden` | Сколько места категория занимает в сводке |
| `mailpilot rule add КАТЕГОРИЯ --from/--recipient/--subject/--body` | Своё правило раскладки |
| `mailpilot mute --from адрес` | Больше не показывать отправителя |
| `mailpilot vip list/add/remove "Имя Фамилия"` | Важные люди, чьи письма всегда наверху |
| `mailpilot doctor` | Проверить настройки и соединение |
| `mailpilot demo [--open]` | Демо-сводка на выдуманных письмах |

## Категории

Категории задаются в `config.yaml` и проверяются сверху вниз: письмо попадает в первую подходящую.
Можно добавлять свои. Правки командами `importance`, `rule`, `mute`, `vip` сохраняются отдельно
в `data/overrides.yaml` и не трогают ваш `config.yaml`.

## Как не теряется контекст

Письма хранятся в базе и собираются в цепочки по заголовкам ответа, по номерам INC (в теме и тексте)
и по теме. У каждой цепочки есть состояние: суть, что решено, что от вас ждут. При новых письмах агент
получает прошлое состояние и только новые письма целиком, поэтому переписка на несколько дней
анализируется целиком, а не по последнему письму.

## Как учится стиль

- `mailpilot learn` берёт ваши ответы из «Отправленных»: в каждом ответе есть цитата исходного письма,
  так получаются пары «что написали — что вы ответили».
- Для каждого черновика агенту подкладываются 3 ваших ответа на похожие письма.
- Когда вы правите черновик перед отправкой, пара «как предложил агент — как отправили вы» сохраняется,
  и в похожих случаях ваша версия становится образцом. `mailpilot learn --style-only` обновит профиль стиля
  с учётом правок.

## Безопасность

- Отправка только командой `mailpilot send`: в терминале она требует ввести «да», агенту разрешено
  добавлять `--yes` только после вашего явного согласия на конкретный текст.
- `mailpilot run` и cron ничего не отправляют.
- Пароль хранится только в `.env`, личные настройки и база — только локально (`.gitignore`).
