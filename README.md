# mailpilot

Локальный помощник по почте и календарю. Каждый день в 17:00 собирает письма с прошлой сводки,
раскладывает их по категориям, собирает переписки в цепочки и делает HTML-сводку с карточками.
Смысловой анализ (суть переписок, проблемы на вашей стороне, конфликты, черновики ответов в вашем стиле)
делает агент в gigacode через скилл. **Ни одно письмо не отправляется без вашего явного «да».**

Всё работает только на вашей машине: почта читается через уже настроенный
[mcp-mail-server](https://github.com/yunfeizhu/mcp-mail-server), данные лежат в локальной базе SQLite,
сводка — один HTML-файл без внешних ресурсов.

## Как это устроено

```
cron 17:00 ──► mailpilot run ──► mcp-mail-server (IMAP) ──► база SQLite
                    │                                         │
                    │  правила: категории, INC, эскалация,    │  цепочки переписки
                    │  важные люди, Jira, Confluence          │  с историей за несколько дней
                    ▼                                         ▼
            HTML-сводка (сразу)        data/work/batch_NN.json (пакеты на анализ)
                                                │
gigacode + скилл mailpilot ◄────────────────────┘
   читает пакеты, пишет result_NN.json ──► mailpilot ingest ──► сводка дополнена смыслом и черновиками
   показывает черновики ──► ваше «да» ──► mailpilot send ──► reply_to_email
```

В gigacode нет режима без окна, а вход через браузер живёт около часа, поэтому модель
вызывается только когда вы сами открываете gigacode. Всё, что можно сделать без модели, делает cron:
забирает почту, раскладывает по категориям, ищет инциденты и эскалации, собирает сводку.

### Что видно в сводке

- **Карточки-счётчики сверху**: по умолчанию «Новые письма», «Требуют внимания», «От руководства»,
  «Ответы готовы». Набор настраивается. Клик по карточке раскрывает нужный раздел и прокручивает к нему.
- **Разделы ниже изначально свёрнуты**, раскрываются кликом по заголовку или стрелке.
  Есть кнопки «Развернуть все» и «Свернуть все».
  - **От руководства**: письма от людей из `digest.vip_senders`, всегда первыми.
  - **Требуют внимания**: где ждут вас, есть эскалация, инцидент, проблема на вашей стороне или стоит
    подключиться. По каждой переписке: суть всей цепочки, предупреждения, что сделать, история.
  - **Ответы готовы**: черновики с кнопками, которые копируют команду отправки или правки.
  - **Встречи**: остаток дня и следующий рабочий день, пересечения подсвечены.
  - **Новые письма**: все категории плитками со списками внутри (Confluence, Jira, уведомления и т. д.).
- Справа вверху переключатель светлой и тёмной темы, выбор запоминается в браузере.

## Установка и развёртывание

Работает на Windows, macOS и Linux. Нужны:

- Python 3.10 или новее;
- [uv](https://docs.astral.sh/uv/) (ставит зависимости и запускает инструмент);
- Node.js 22.13 или новее и npm (для mcp-mail-server);
- gigacode (для анализа и черновиков; без него сводка тоже собирается, но без смыслового разбора).

```bash
git clone https://github.com/Olych03/giga_mailer mailpilot
cd mailpilot
uv sync                           # зависимости в .venv внутри папки
uv run mailpilot demo --open      # демо-сводка на выдуманных письмах, почта не нужна
uv run mailpilot init             # создаст config.yaml и .env из примера
```

Дальше все команды выполняются из папки `mailpilot` через `uv run mailpilot ...`.
Если удобнее без `uv run`, установите инструмент как команду: `uv tool install .`, тогда хватит `mailpilot ...`.

**Закрытый контур.** Если интернет-репозитории недоступны, укажите внутренние зеркала:
для Python `UV_INDEX_URL=https://<зеркало>/simple` (или `--index-url` у `uv sync`),
для npm `npm config set registry https://<зеркало>/`. Можно заранее поставить сервер почты
глобально (`npm install -g mcp-mail-server`) и в `config.yaml` указать `mcp.command: mcp-mail-server`
и `mcp.args: []`, тогда `npx` не ходит в сеть при каждом запуске.

Файл `uv.lock` в репозиторий не кладётся намеренно: `uv sync` подберёт версии из вашего зеркала.

## Переменные среды и пароль

Настройки лежат в двух файлах рядом друг с другом, оба создаёт `mailpilot init`, оба не попадают в git:

| Файл | Что в нём |
|---|---|
| `config.yaml` | Все настройки: кто вы, параметры почты, люди, категории, вид сводки |
| `.env` | Секреты, прежде всего пароль: `EMAIL_PASS=...` |

Параметры подключения к почте задаются в блоке `mcp.env` файла `config.yaml`. Это те же переменные,
с которыми у вас уже работает mcp-mail-server:

```yaml
mcp:
  command: npx
  args: ["-y", "mcp-mail-server"]
  env:
    IMAP_HOST: imap.example.com
    IMAP_PORT: "993"
    IMAP_SECURE: "true"        # сервер работает только с TLS
    SMTP_HOST: smtp.example.com
    SMTP_PORT: "465"
    SMTP_SECURE: "true"
    EMAIL_USER: o.ivanova@example.com
```

А в `.env`:

```
EMAIL_PASS=ваш_пароль
```

Как собираются переменные для сервера почты:

1. берутся переменные окружения системы;
2. к ним добавляется `.env` (значения из `.env` не перезаписывают уже заданные в системе);
3. поверх кладётся блок `mcp.env` из `config.yaml`.

То есть любую переменную можно держать в `.env` или в системе вместо `config.yaml`, если удалить её из
`mcp.env`. Пароль в `config.yaml` не пишите. Числа и `true/false` в `mcp.env` берите в кавычки.

Ещё одна переменная: `MAILPILOT_CONFIG=/путь/к/config.yaml` — если конфиг лежит не в текущей папке
(то же самое делает ключ `--config` у любой команды). Для правки черновиков используется редактор
из `EDITOR` (по умолчанию notepad на Windows, nano или vi на macOS и Linux).

## Первый запуск

1. В `config.yaml` заполните блок `me` и параметры почты, в `.env` пароль.
2. `uv run mailpilot doctor` — проверит соединение и покажет точные имена папок.
   Имя папки «Отправленные» впишите в `mailboxes.sent`, если сервер не нашёл её сам.
3. Настройте людей и категории (раздел [Настройка под себя](#настройка-под-себя)).
4. `uv run mailpilot run --open` — первая сводка за последние сутки (`fetch.initial_hours`).
5. `uv run mailpilot learn --days 90` — соберёт ваши ответы из «Отправленных» как образцы стиля.
6. Откройте gigacode в папке mailpilot и скажите «обнови профиль стиля», затем «разбери почту».

## Скилл для gigacode

Скопируйте папку `skill/mailpilot` в папку скиллов gigacode (формат стандартный: `SKILL.md` с описанием
и папка `references`). Затем в gigacode:

- «разбери почту» — агент проанализирует пакеты и дополнит сводку сутью, предупреждениями и черновиками;
- «покажи черновики» — пройдётся по черновикам и отправит только то, на что вы скажете «да»;
- «обнови профиль стиля» — после `mailpilot learn` напишет `data/style.md` (его можно править руками);
- «добавь важного человека…», «сделай категорию юристов важной», «не показывай письма от…» — агент
  сам вызовет нужную команду настройки.

Если gigacode запускается не из папки mailpilot, скажите агенту путь к ней.

## Запуск по расписанию

**Linux и macOS** (`crontab -e`), по будням в 17:00:

```
0 17 * * 1-5 cd /путь/к/mailpilot && /путь/к/uv run mailpilot run >> data/cron.log 2>&1
```

Полный путь к `uv` покажет `which uv`. На macOS cron может потребовать разрешения «Полный доступ к диску».

**Windows** (Планировщик заданий), по будням в 17:00:

```
schtasks /Create /TN mailpilot /SC WEEKLY /D MON,TUE,WED,THU,FRI /ST 17:00 ^
  /TR "cmd /c cd /d C:\путь\к\mailpilot && uv run mailpilot run >> data\cron.log 2>&1"
```

Чтобы сводка сама открывалась после сборки, поставьте `digest.open_after_render: true`.
На Windows календарь читается из десктопного Outlook (он должен быть запущен в той же учётной записи).
На macOS и Linux встречи берутся из писем-приглашений.

## Настройка под себя

У каждого свой `config.yaml`, поэтому и сводка у каждого своя. Например, вам важны обращения с ПРОМ,
а коллеге переписка с юристами: коллега добавляет категорию «Юристы» с `importance: high`,
а ПРОМ ставит в `low`.

Настраивать можно двумя способами:

- **править `config.yaml`** — всё в одном месте, с комментариями;
- **командами** (`mailpilot vip`, `importance`, `rule`, `mute`) или словами агенту. Такие правки
  сохраняются отдельно в `data/overrides.yaml` и накладываются поверх `config.yaml`, сам файл не меняется.

Изменения действуют со следующего запуска. Правила категорий применяются к новым письмам.

### О себе

```yaml
me:
  name: "Иванова Ольга"                    # показывается в заголовке сводки
  addresses: ["o.ivanova@example.com"]     # все ваши адреса, включая старые и алиасы
  my_side_keywords: ["Система Альфа", "команда Альфа"]
```

- `addresses` — по ним инструмент понимает, какие письма в цепочке ваши и ждут ли вашего ответа.
- `my_side_keywords` — названия вашей системы, команды, модуля. Если они встречаются в чужих письмах,
  переписка помечается «проблема на вашей стороне».

### Люди: на кого реагировать в первую очередь

Есть два списка, и они делают разное:

| Параметр | Где проверяется | Что происходит |
|---|---|---|
| `digest.vip_senders` | **отправитель** письма | Переписка попадает в раздел «От руководства» в самом верху |
| `escalation.people` | **адресаты** (Кому и Копия) | Переписка помечается как эскалация и поднимается в «Требуют внимания» |

```yaml
digest:
  vip_senders: ["Виктор Громов", "Зарецкий", "p.lebedev@example.com"]

escalation:
  keywords: ["до сих пор не", "срочно"]   # слова в тексте, которые тоже означают эскалацию
  people: ["Петров", "Сидорова"]
  long_thread_messages: 6                  # длинная цепочка без вашего ответа тоже тревожна
```

Как писать людей:

- можно «Имя Фамилия», просто фамилию или адрес целиком;
- mcp-mail-server отдаёт только адреса без имён, поэтому фамилия ищется **латиницей в адресе**
  с учётом разных вариантов транслитерации: «Зарецкий» найдётся в `zaretskiy@`, `zaretsky@`,
  `AAZaretskiy@` и т. п.; в записи «Имя Фамилия» ищется фамилия, частые имена пропускаются;
- если у человека нестандартный адрес (например, `apz@...`), пишите адрес целиком — это надёжнее всего;
- проверить, кто в списке важных людей: `mailpilot vip list`.

Командами:

```bash
uv run mailpilot vip add "Павел Лебедев"
uv run mailpilot vip remove "Виктор Громов"
uv run mailpilot vip list
```

Список `escalation.people` командами не меняется, только в `config.yaml`.

### Категории

Категории задаются списком `categories` и проверяются **сверху вниз**: письмо попадает в первую
подходящую. Одна категория с `default: true` ловит всё остальное (по умолчанию «Текучка»).

```yaml
categories:
  - id: prom                      # короткий идентификатор латиницей, используется в командах
    title: Обращения с ПРОМ       # название в сводке
    importance: high              # high | normal | low | hidden
    analyze: true                 # отдавать цепочки агенту на смысловой анализ
    drafts: true                  # разрешить агенту предлагать черновики ответов
    color: "#d64545"              # цвет метки в сводке
    match:
      - recipients_contain: ["prom-support@example.com"]
```

**Важность** определяет, где категория видна в сводке:

| `importance` | Где видно |
|---|---|
| `high` | «Требуют внимания», первыми |
| `normal` | «Требуют внимания», после `high` |
| `low` | только плиткой в «Новых письмах» |
| `hidden` | нигде, только счётчик «Скрыто настройками» внизу |

**Условия `match`.** Элементы списка соединяются через ИЛИ, ключи внутри одного элемента через И:

```yaml
match:
  - from_contains: ["legal@example.com"]                    # ИЛИ
  - recipients_contain: ["legal@example.com"]               # ИЛИ
  - subject_contains: ["договор"]
    from_contains: ["@partner.example.com"]                 # (тема И отправитель)
```

| Ключ | Что проверяет |
|---|---|
| `recipients_contain` | кусок адреса в Кому или Копии |
| `from_contains` | кусок адреса отправителя |
| `from_regex` | регулярное выражение по адресу отправителя |
| `subject_contains` | кусок темы |
| `subject_regex` | регулярное выражение по теме |
| `body_regex` | регулярное выражение по тексту письма |

Сравнение без учёта регистра. Сервер почты отдаёт только адреса, поэтому в `from_contains`
и `recipients_contain` пишите адреса или их части латиницей, а не имена.

**Особая обработка уведомлений**: `extractor: jira` превращает письма Jira в список задач,
`extractor: confluence` — в список изменённых страниц по пространствам.

**Пример: своя категория «Юристы»** (вставьте выше категории по умолчанию):

```yaml
  - id: legal
    title: Юристы
    importance: high
    analyze: true
    drafts: true
    color: "#7c3aed"
    match:
      - from_contains: ["legal@example.com", "yurist"]
      - recipients_contain: ["legal@example.com"]
```

Командами:

```bash
uv run mailpilot categories                                  # список категорий и их важность
uv run mailpilot importance jira hidden                      # изменить важность
uv run mailpilot rule add legal --from "@lawfirm.example"    # письма с этого домена → «Юристы»
uv run mailpilot rule add notifications --subject "^\[Мониторинг\]"
uv run mailpilot mute --from "digest@news.example"           # больше не показывать отправителя
```

`rule add` принимает `--from`, `--recipient` (кусок адреса), `--subject`, `--body` (регулярные выражения);
несколько ключей в одной команде соединяются через И. Правило проверяется раньше правил самой категории.

**Инциденты** определяются по `incident_regex` (по умолчанию `\bINC\d{4,}\b`) в теме и тексте.
Письма с одним номером INC собираются в одну цепочку, даже если темы разные.

### Карточки сверху

```yaml
digest:
  tiles:
    - {type: new, title: "Новые письма"}
    - {type: attention, title: "Требуют внимания"}
    - {type: vip, title: "От руководства"}
    - {type: drafts, title: "Ответы готовы"}
    - {type: category, category: prom, title: "ПРОМ", tone: red}
```

| `type` | Что считает |
|---|---|
| `new` | все новые письма за период |
| `attention` | переписки, которые требуют внимания |
| `vip` | переписки от важных людей |
| `drafts` | готовые ответы на согласование |
| `escalations` | переписки с эскалацией |
| `incidents` | переписки с номерами INC |
| `calendar` | встречи на следующий рабочий день |
| `category` | письма одной категории (укажите `category: id`) |

`title` — своё название (оно же становится названием раздела), `tone` — цвет:
`blue`, `red`, `violet`, `green`, `amber`, `neutral`. Порядок карточек любой, порядок разделов постоянный.

### Все остальные параметры

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `source` | `mcp` | `mcp` — настоящая почта, `demo` — выдуманные письма |
| `data_dir` | `data` | Папка для базы, сводок и пакетов (относительно `config.yaml`) |
| `mailboxes.inbox` | `INBOX` | Папка входящих |
| `mailboxes.sent` | `null` | Папка «Отправленные»; `null` — сервер найдёт сам |
| `mailboxes.extra` | `[]` | Дополнительные папки, если правила Outlook раскладывают почту по ним |
| `fetch.initial_hours` | `24` | За сколько часов забрать почту при самом первом запуске |
| `fetch.batch_size` | `20` | Сколько писем запрашивать за один вызов сервера |
| `digest.carry_over_days` | `5` | Сколько дней показывать переписки, где всё ещё ждут вашего ответа |
| `digest.open_after_render` | `false` | Открывать сводку в браузере после сборки |
| `analysis.batch_threads` | `8` | Сколько цепочек в одном пакете для агента |
| `analysis.max_message_chars` | `2500` | Ограничение длины одного письма в пакете |
| `analysis.max_full_messages` | `10` | Сколько последних писем цепочки передавать целиком |
| `analysis.examples_per_thread` | `3` | Сколько ваших прошлых ответов подкладывать как образцы |
| `calendar.source` | `auto` | `auto`, `outlook` (Windows), `ics_mail` (из приглашений) или `none` |
| `incident_regex` | `\bINC\d{4,}\b` | Как выглядит номер инцидента |
| `signature` | `""` | Подпись, которая добавляется к отправляемым ответам |

## Работа из командной строки

### Обычный день

```bash
# 17:00 cron сам запускает: uv run mailpilot run
uv run mailpilot render --open        # открыть свежую сводку
# в gigacode: «разбери почту» — агент дополнит сводку сутью и черновиками
uv run mailpilot drafts               # список черновиков
uv run mailpilot draft show 3         # посмотреть черновик целиком
uv run mailpilot draft edit 3         # поправить в редакторе (или --text "..." / --file ответ.txt)
uv run mailpilot send 3               # отправить: покажет письмо и попросит ввести «да»
uv run mailpilot draft reject 4       # отклонить ненужный черновик
```

Сводку можно собрать вручную в любое время: `uv run mailpilot run --open`. Период всегда считается
с прошлой сводки.

### Все команды

| Команда | Что делает |
|---|---|
| `mailpilot init [--force]` | Создать `config.yaml` и `.env` из примера |
| `mailpilot doctor` | Проверить настройки, соединение с почтой, показать папки |
| `mailpilot run [--open]` | Забрать почту, собрать сводку и пакеты на анализ (для cron) |
| `mailpilot fetch` | Только забрать новые письма |
| `mailpilot prepare` | Только подготовить пакеты на анализ |
| `mailpilot ingest [--open]` | Принять результаты анализа от агента и пересобрать сводку |
| `mailpilot render [--open]` | Пересобрать последнюю сводку |
| `mailpilot status` | Состояние анализа и черновиков (JSON, для скилла) |
| `mailpilot drafts` | Черновики на согласование |
| `mailpilot draft show/edit/reject ID` | Посмотреть, поправить (`--text`, `--file` или редактор), отклонить |
| `mailpilot send ID` | Отправить черновик после подтверждения «да» |
| `mailpilot learn [--days 90] [--style-only]` | Образцы ответов из «Отправленных» и пакет для профиля стиля |
| `mailpilot categories` | Список категорий и их важность |
| `mailpilot importance КАТЕГОРИЯ high\|normal\|low\|hidden` | Изменить важность категории |
| `mailpilot rule add КАТЕГОРИЯ --from/--recipient/--subject/--body` | Своё правило раскладки |
| `mailpilot mute --from адрес` | Больше не показывать отправителя |
| `mailpilot vip list/add/remove "Имя Фамилия"` | Важные люди, чьи письма всегда наверху |
| `mailpilot demo [--open] [--raw]` | Демо-сводка на выдуманных письмах |

Ключ `--config путь` ставится перед командой: `mailpilot --config ~/work/config.yaml run`.
Подсказка по любой команде: `mailpilot КОМАНДА --help`.

## Как не теряется контекст и как учится стиль

Письма хранятся в базе и собираются в цепочки по заголовкам ответа, по номерам INC (в теме и тексте)
и по теме. У каждой цепочки есть состояние: суть, что решено, что от вас ждут. При новых письмах агент
получает прошлое состояние и только новые письма целиком, поэтому переписка на несколько дней
анализируется целиком, а не по последнему письму.

Стиль:

- `mailpilot learn` берёт ваши ответы из «Отправленных»: в каждом ответе есть цитата исходного письма,
  так получаются пары «что написали — что вы ответили».
- Для каждого черновика агенту подкладываются ваши ответы на похожие письма.
- Когда вы правите черновик перед отправкой, пара «как предложил агент — как отправили вы» сохраняется,
  и в похожих случаях ваша версия становится образцом. `mailpilot learn --style-only` обновит профиль стиля
  с учётом правок. Профиль лежит в `data/style.md`, его можно править руками.

## Где что лежит

```
mailpilot/
├── config.yaml            ваши настройки (не в git)
├── .env                   пароль (не в git)
├── skill/mailpilot/       скилл для gigacode
└── data/                  всё локальное (не в git)
    ├── mailpilot.db       база писем, цепочек и черновиков
    ├── digests/           сводки; latest.html — последняя
    ├── work/              пакеты на анализ и ответы агента (обработанные — в work/done)
    ├── style.md           профиль вашего стиля
    ├── overrides.yaml     правки, сделанные командами
    ├── attachments/       сохранённые приглашения .ics
    ├── mcp-server.log     журнал сервера почты
    └── cron.log           журнал запусков по расписанию
```

Чтобы начать с чистого листа, удалите папку `data` (настройки в `config.yaml` останутся).

## Частые проблемы

| Что видно | Что сделать |
|---|---|
| «Не задан пароль» | Добавьте `EMAIL_PASS=...` в `.env` рядом с `config.yaml` |
| «Не найден файл настроек» | Запустите из папки mailpilot, укажите `--config` или `MAILPILOT_CONFIG` |
| `npx` не найден в PATH | Установите Node.js; для cron укажите полный путь в `mcp.command` |
| Ошибка соединения в `doctor` | Сверьте `mcp.env` с рабочими настройками сервера, смотрите `data/mcp-server.log` |
| Человек из списка не находится | Укажите его адрес целиком вместо фамилии |
| Письмо попало не в ту категорию | `mailpilot rule add нужная_категория --from ...` или поправьте порядок категорий |
| В сводке нет сути и черновиков | Откройте gigacode и скажите «разбери почту» |
| Календарь пустой на Windows | Запустите десктопный Outlook или поставьте `calendar.source: ics_mail` |

## Безопасность

- Отправка только командой `mailpilot send`: в терминале она требует ввести «да», агенту разрешено
  добавлять `--yes` только после вашего явного согласия на конкретный текст.
- `mailpilot run` и cron ничего не отправляют.
- Пароль хранится только в `.env`, личные настройки и база — только локально (`.gitignore`).
- Ничего не уходит наружу: почта читается с вашего сервера, модель вызывается только из gigacode.
