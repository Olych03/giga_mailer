# mailpilot: анализ почты и черновики ответов

mailpilot — локальная программа. Почту она забирает сама (cron в 17:00 запускает `mailpilot run`),
раскладывает правилами и готовит **пакеты на анализ** в `data/work/batch_NN.json`. Твоя работа —
смысловой анализ этих пакетов, черновики ответов и согласование с пользователем.

Все команды запускай в папке проекта mailpilot: `uv run mailpilot <команда>`. Если текущая папка
другая, добавляй путь: `uv run --directory <папка mailpilot> mailpilot <команда>` (путь к папке
пользователь указывает при установке скилла; если не знаешь его, спроси).

## Главное правило

**Никогда не отправляй письмо без явного «да» пользователя на конкретный текст.**
Покажи текст черновика, кому он уйдёт и копию. Только после ответа «да», «отправляй» или похожего
на этот конкретный черновик выполни `uv run mailpilot send <ID> --yes`. Если пользователь попросил
поправить текст — сначала `uv run mailpilot draft edit <ID> --text "..."`, покажи новый вариант и снова спроси.
Одно «да» относится к одному черновику. Не отправляй пачкой без перечня.

## Сценарий «разбери почту» / «сводка»

1. `uv run mailpilot status` — посмотри, есть ли пакеты (`batches`) и когда была последняя сводка.
   Если пакетов нет и сводка старая или её нет — `uv run mailpilot run`, затем снова `status`.
2. Для каждого `batch_NN.json` из списка:
   - прочитай файл целиком;
   - проанализируй каждую цепочку по правилам из [references/analysis.md](references/analysis.md);
   - запиши результат в файл из поля `result_file` (JSON вида `{"threads": [ ... ]}`), по одному объекту
     на каждую цепочку пакета, с тем же `thread_id`.
3. `uv run mailpilot ingest` — программа примет результаты и пересоберёт HTML-сводку. В ответе будет путь к ней.
4. Коротко расскажи пользователю главное: что требует его действия, где проблемы на его стороне,
   где конфликт и стоит подключиться, сколько черновиков готово. Дай путь к HTML-сводке.
5. Предложи пройтись по черновикам.

Если `ingest` сообщил `missing` или `errors` — исправь соответствующие result-файлы и запусти `ingest` снова.

## Сценарий «черновики»

1. `uv run mailpilot drafts` — список черновиков с текстами.
2. Показывай по одному: кому, тема, текст. Спроси: отправить, поправить или отклонить.
3. Отправить — только после явного «да»: `uv run mailpilot send <ID> --yes`.
4. Поправить — `uv run mailpilot draft edit <ID> --text "<новый текст>"`, покажи результат, спроси снова.
   Правки пользователя программа запоминает и учится на них.
5. Отклонить — `uv run mailpilot draft reject <ID>`.

## Сценарий «обнови профиль стиля» / первичная настройка

1. Первый раз: `uv run mailpilot learn --days 90` (позже достаточно `uv run mailpilot learn --style-only`).
2. Прочитай `data/work/style_request.json`: там ответы пользователя (`replies`) и его правки черновиков (`edits`).
3. Напиши профиль стиля в файл из поля `output_file` по правилам из [references/style.md](references/style.md).
   Если есть `current_profile`, обнови его, а не пиши с нуля.

## Настройка категорий по просьбе пользователя

- «Письма от Иванова показывай первыми» → `uv run mailpilot vip add "Иван Иванов"` (список: `vip list`, убрать: `vip remove`)
- «Мне важнее ПРОМ / переписка с юристами» → `uv run mailpilot importance <категория> high`, менее важное → `low`
- «Jira больше не показывай» → `uv run mailpilot importance jira hidden`
- «Письма от X не показывай» → `uv run mailpilot mute --from x@...`
- «Письма с темой Y относи к ПРОМ» → `uv run mailpilot rule add prom --subject "Y"`
- Список категорий: `uv run mailpilot categories`. После изменений: `uv run mailpilot render`.

## Чего не делать

- Не читай почту через MCP-инструменты напрямую для сводки: всё нужное уже в пакетах.
- Не придумывай факты, которых нет в письмах. Если не уверен — так и напиши в `summary`.
- Не меняй `config.yaml` без просьбы пользователя.
